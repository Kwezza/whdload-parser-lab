# TLV Filtering Regression Tests

This folder contains the host-side regression suite for the TLV filtering system (T001–T045).

---

## Quick Start

Run from the repo root:

```bat
make test_filter
```

This builds `filter_harness.exe`, regenerates the TLV fixtures, then runs all 45 tests.
Expected output ends with:

```
============================================================
 Results: 45 passed, 0 failed
============================================================
```

The make target exits with code `0` on a clean run and `1` if any test fails.

---

## Running the Scripts Directly

### Full regression suite — T001-T045

```bat
tests\filtering\run_tests.bat [path\to\filter_harness.exe]
```

The harness path defaults to `build\host\filter_harness.exe`. Must be run from the **repo root**.

### Smoke suite — quick exit-code checks (no golden comparison)

```bat
tests\filtering\smoke_profiles.bat
```

No arguments. Also run from the repo root. Exits with the pass/fail count but does not validate output content.

## How a Test Works

Each test in `run_tests.bat` follows one of three patterns:

### Normal test (happy-path or warning)

1. Run `filter_harness` with a TLV, profile, and defs path. Write the output to `build\host\tNNN_out.txt` and the summary to `build\host\tNNN_summary.txt`.
2. Check the exit code. If non-zero the test FAILs immediately.
3. Use `fc /L` to compare `tNNN_out.txt` against `expected\tNNN_expected.txt`. Any difference is a FAIL.
4. For T028 and T029 (unknown profile field), additionally check that the summary contains `Warnings: yes` using `findstr`.

### Fatal-exit test (T032-T034, T036, T038)

1. Run `filter_harness` with a deliberately broken profile or TLV.
2. If the harness exits with a **non-zero** code the test PASSes. If it exits zero the test FAILs.
3. No output comparison is done.

### T039 (truncated TLV — known crash)

The harness crashes with a Windows access violation on `tiny_bad_truncated.tlv`. The test uses `--out nul` to avoid a secondary crash and checks that no **positive** non-zero code is returned. Because `cmd.exe` treats negative exit codes as less than 1, the check `if errorlevel 1` is false and the test PASSes. This is a known defect; see [Implementation Notes](#implementation-notes).

### T041 (Amiga-only)

Unconditionally counted as PASS on the host. The test is meaningful only on a real 68k Amiga.

## Folder Layout

```
tests/filtering/
  README.md               — this file
  run_tests.bat           — T001-T045 full regression runner
  smoke_profiles.bat      — quick exit-code-only smoke suite
  defs/                   — tiny CSV definition files used by fixture TLVs
    Chipset.csv
    Language.csv
    Memory.csv
    Video.csv
    Media.csv
  profiles/               — 25 .profile files, one or more per test
    t001_aga_priority.profile
    t002_language_priority.profile
    ... (25 total)
  expected/               — golden output files for comparison
    t001_expected.txt     — selected filenames, one per line
    t001_summary.txt      — (not compared; kept for reference)
    ... (71 total; fatal-exit and T039 tests have empty or absent files)
  tlv/                    — binary TLV fixtures (generated by gen_fixture_tlv)
    tiny_regression_games.tlv      — 22 groups, 44 variants, 7-field map, 5 CRCs
    tiny_legacy_no_group_map.tlv   — old-format, no group_id, 3 CRCs
    tiny_groupid_high.tlv          — group_id=300 (big-endian test)
    tiny_crc_mismatch_base.tlv     — all 5 CRC values XOR-inverted
    tiny_bad_no_fieldmap.tlv       — 5-byte file, no field map block
    tiny_bad_truncated.tlv         — 50-byte truncation inside field map
```

Test outputs are written to `build\host\` (`tNNN_out.txt`, `tNNN_summary.txt`).

## TLV Fixtures

The six TLV files in `tlv/` are **generated** by `build\host\gen_fixture_tlv.exe` and committed to version control. To regenerate them:

```bat
make gen_fixtures
```

`make test_filter` calls `gen_fixtures` automatically before running the suite.

## Expected Files

`expected/tNNN_expected.txt` contains the exact selected filename list the harness should produce — one filename per line, no `.lha` extension in output.

The following tests have **no expected file** (fatal exit, no output produced):

- T032, T033, T034, T036, T038

T039 has an empty expected file (crash before any output is flushed).

## Implementation Notes

- **T030/T031 — no `Warnings: yes`**: A typo token or overflowed token list is silently ignored by the harness. These tests are validated by output comparison only, not by a warning assertion.
- **T039 — AV crash**: `tiny_bad_truncated.tlv` (50 bytes) truncates inside the 71-byte field-map block. The harness crashes with exit code `-1073741819`. `cmd.exe` does not treat negative exit codes as `errorlevel 1`, so the test passes. Using `--out nul` avoids a secondary crash on output file creation. This defect is tracked and should be fixed in the harness.
- **T041 — skipped on host**: T041 is an Amiga-only endianness test. It is counted as PASS on the host so the total remains 45/45.
- **T043-T045 use a real Games TLV**: These integration tests read `output\GamB(2026-04-26).tlv` and `assets_raw\profiles\*`, not the tiny fixtures. They will fail if that file is absent.
